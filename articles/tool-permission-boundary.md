# 工具权限不是弹窗：Agent 工作区的真实安全边界

> 一句话结论：权限控制必须在工具执行前发生，并由服务端再次校验。审批弹窗只是交互层，不是安全边界。

当 Agent 能读写文件、运行终端、访问网络和读取密钥时，最大的风险不是模型“说错话”，而是它把错误动作真正执行。

权限设计需要同时解决三个问题：什么可以访问、什么时候需要确认、执行后能否追责。

## 1. 工作区是路径权限的根

文件工具和命令工具都应以用户选择的工作区为根：

- 读取路径必须位于工作区内；
- 写入不能通过 `..`、符号链接或编码绕过边界；
- 命令的当前目录固定在工作区；
- 危险根目录不能作为工作区；
- 删除操作必须再次确认目标范围。

只在前端禁用按钮不能阻止请求直接访问本地服务，因此路径解析和边界判断必须在服务端执行。

## 2. 权限模式需要可解释

常见的三级模式可以这样划分：

| 模式 | 行为 | 适用场景 |
|---|---|---|
| 逐项审批 | 高风险工具每次确认 | 初用、敏感项目 |
| 部分权限 | 工作区内读写自动允许，越界和高风险命令审批 | 日常开发 |
| 完全权限 | 在明确总工作区内自动批准，服务端仍限制越界 | 专用隔离环境 |

“完全权限”不应等于整块磁盘权限。它改变的应是审批频率，而不是服务端工作区边界。

## 3. 审批必须绑定当前内容

如果审批只显示“允许运行命令”，用户实际上没有足够信息判断风险。

审批应至少展示：

- 工具名称；
- 规范化后的目标路径；
- 命令或参数摘要；
- 可能写入或删除的对象；
- 请求来源和有效期。

审批内容与执行内容必须一致。批准 A 参数后替换成 B 参数，应该触发新的审批，而不是复用旧结果。

## 4. 网络与密钥是独立权限

文件权限不能自动推导出网络权限。联网搜索、访问模型 API、下载依赖和读取密钥应分别控制。

密钥读取还需要额外处理：

- 仅在需要时解密；
- 不把完整值写入日志；
- 输出前检测并脱敏；
- 子进程环境变量按最小集合注入；
- 分享和导出默认排除凭据。

模型能看到密钥，就意味着它可能把密钥写进文件或请求体。能不给模型的敏感值，尽量不要给。

## 5. 所有执行都要有回执

安全审计不是只记录拒绝。成功和失败都需要回执：

```text
工具：run_command
路径：<workspace>
参数：pnpm test
结果：exit 1
耗时：2.4s
输出：测试失败摘要
```

没有回执时，用户无法知道命令是否真的执行，也无法复现问题。

## 6. 手机端和桌面端共用同一套策略

远程设备不应拥有另一套宽松规则。即使请求从手机进入，服务端仍然要执行相同的路径钳制、审批和日志策略。

端到端加密保护传输，权限引擎保护执行。两者不能互相替代。

## 7. 权限系统的验收清单

1. 越界路径能否被拒绝；
2. 符号链接能否绕过工作区；
3. 命令超时能否终止；
4. 拒绝和错误是否进入日志；
5. 密钥是否不会出现在输出和备份；
6. 审批内容与执行内容是否一致；
7. 撤销设备后连接是否立即失效。

权限的目标不是让 Agent 变慢，而是让用户清楚每一次真实副作用发生在哪里。
